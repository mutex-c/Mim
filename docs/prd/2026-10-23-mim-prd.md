# Mim (M Instant Message) 即时通讯平台 - 产品需求文档 (PRD)

---

## 1. 文档概述与项目背景

### 1.1 项目定位
本项目（**Mim**，即 **M Instant Message**）定位为**现代化、高可靠、跨三端（Web、Desktop、Android）的即时通讯系统**，具备**双模部署架构（Dual-Mode Architecture）**：
1. **轻量单体交付模式（Edge & Private Monolith）**：
   * 基于 Go 1.22 原生高并发模型与 SQLite 3 WAL 嵌入式持久化，支持零外部中间件启动（内存底噪 < 30MB），面向边缘计算、内网隔离与中小团队极简私有化交付。
2. **分布式微服务集群模式（Enterprise Microservices Cluster）**：
   * 采用 **长连接网关（mim-gateway）+ 无状态业务逻辑（mim-logic）+ 异步推送削峰（mim-transfer）** 架构。
   * 结合 **Etcd v3 动态服务注册发现**、**Redis 7 跨节点路由与原子时序**、**Kafka 3.x 消息削峰管线**、**MySQL 8 分布式关系存储** 与 **Prometheus 生产级指标监控**，支持水平弹性扩容至百万级并发连接。

### 1.2 核心价值与工程亮点
1. **双模自由切换，代码零分支**：
   * 业务核心抽象化适配：数据库支持 SQLite 3 (WAL) 与 MySQL 8 动态切换；消息管道支持 Kafka 3.x 与内存队列平滑降级；服务发现支持 Etcd v3 租约监听与静态配置回退。
2. **时序与严格可靠性保证 (At-Least-Once Delivery)**：
   * **分布式单调递增 SeqId**：基于 Redis 7 原子 `INCR` 分配会话递增序列号，并由数据库基线自愈预热，保证消息绝对全局有序，杜绝多实例冲突。
   * **完整 3 段式 ACK 状态机**：`SENT` (1, 发送回执) -> `DELIVERED` (2, 接收方送达回执 `CmdDeliveryAck` 0x0103) -> `READ` (3, 接收方已读回执 `CmdReadReceipt` 0x0401)，多端游标双向同步。
   * **同端互踢与多端协同 (FR-AUTH-03)**：支持跨节点同平台设备挤占互踢通知（`CmdKickOut` 0x0006），多端在线聚合同步与防串号。
3. **高效混合通信契约**：
   * 自定义 24 字节定长二进制帧头（魔数 `0x4D49`、版本、Flags、CmdType、SeqID、载荷长度与 CRC32 校验），支持心跳保活、双向 ACK、实时推送、增量同步与点对点 WebRTC 信令中继。
   * 载荷层支持 Protobuf 二进制与 JSON 双模解析（通过 Flags 区分），兼顾高吞吐与多端协议适配敏捷性。
4. **全链路安全防护与防越权**：
   * 全链路 JWT 统一鉴权，彻底剔除开发期测试参数绕过隐患。
   * 会话隔离与防水平越权（IDOR）：获取历史记录、撤回消息、删除消息与清空会话严格校验会话成员及消息发送人所有权。
   * 文件防盗链机制：文件上传生成基于 HMAC-SHA256 的时效访问签名（`?sign=`），杜绝 IDOR 遍历脱库；路径强制校验防目录穿越。
   * 敏感信息脱敏：用户私有 AI Key 接口回显自动脱敏，且更新配置时支持掩码识别防误覆盖。
5. **生产级可观测性 (Prometheus Metrics)**：
   * 全链路暴露标准 `/metrics` 监控端点，实时采集在线连接数（按平台细分）、收发消息吞吐量、ACK/已读回执计数、踢人事件计数与消息流转延迟直方图。
6. **三端原生体验**：
   * **Windows / macOS 桌面端**：基于 **Tauri v2 (Rust 核心) + Vue 3**，杜绝 Electron 内存膨胀，安装包 < 15MB，内存占用 < 40MB。
   * **Android 移动端**：基于 **Kotlin + Jetpack Compose 纯原生**，提供 120Hz 丝滑交互、本地 Room 缓存与原生 WebRTC 支持。
   * **Web 网页端**：基于 **Tailwind CSS + 现代化轻质感设计系统**（暗黑/浅色毛玻璃、流式交互、丰富微动效）。

## 3. 功能需求详述 (FR)

### 3.1 认证与账号服务 (`auth`)
* **FR-AUTH-01 注册与账号密码登录**：支持账号注册、密码登录与安全退出。
* **FR-AUTH-02 双 Token 凭据机制**：采用 `AccessToken (短效)` + `RefreshToken (长效)` 机制，客户端请求拦截器自动无感续签。
* **FR-AUTH-03 多设备协同与同端互踢**：
  * 支持同一用户在不同设备（Web、Desktop、Android）同时建立 WebSocket 连接，服务器连接 Hub 自动按 `UserID` 聚合多端设备。
  * **同平台设备互踢**：同一用户在同一平台（如两个 Chrome 标签页或两台 Android 手机）重复登录时，新连接踢出旧连接，服务端下发 `CmdKickOut (0x0006)` 二进制帧并优雅断开连接。
  * **分布式跨节点互踢**：在微服务网关集群环境下，通过 Redis PubSub (`mim:channel:kickout`) 广播挤占事件，各网关节点毫秒级驱逐旧设备长连接。
  * **多端消息漫游同步**：某端发送消息时，服务端通过排除机制（`SendToUserExclude`）向该用户的其他在线端推送时序消息，实现多端实时状态同步。
* **FR-AUTH-04 账号安全**：密码强制采用 `bcrypt` 强哈希加盐存储，支持修改密码与安全注销。

### 3.2 用户与关系链服务 (`user`)
* **FR-USER-01 个人资料管理**：用户基本信息（昵称、签名、头像、自定义配置），支持前端图片更新与个性化设置。
* **FR-USER-02 好友关系全流程流转**：
  * 发起好友申请 -> 填写验证信息 -> 接收端实时红点通知与申请列表展示。
  * 状态机流转：`待审核(PENDING)`、`已同意(AGREED)`、`已拒绝(REJECTED)`。
* **FR-USER-03 好友关系管理**：支持好友列表展示、好友搜索、双向/单向好友解除。
* **FR-USER-04 实时在线感知**：服务端连接 Hub 与 Redis 在线路由表实时维护活跃客户端实例，支持跨节点精准判定用户在线状态。

### 3.3 实时即时通讯系统 (`chat`)
* **FR-CHAT-01 消息类型全覆盖**：
  1. **纯文本与富文本**：支持 Markdown 片段与超链接渲染。
  2. **表情与表情包**：Unicode Emoji 表情面板、自定义表情包保存与一键发送。
  3. **图片消息**：支持图片上传、压缩、缩略图展示、原图灯箱查看。
  4. **语音留言**：客户端录音上传、音频即时编码与按秒进度播放。
  5. **文件消息**：支持多类型文件上传、展示文件大小、专用图标与一键下载。
* **FR-CHAT-02 消息完整生命周期与 ACK 状态机**：
  * **状态机流转**：
    * `MsgStatusSending (0)`：客户端本地生成 `client_msg_id` 并挂起；
    * `MsgStatusSent (1)`：服务端成功入库并生成 `seq_id`，立即返回 `CmdMessageAck (0x0102)`；
    * `MsgStatusDelivered (2)`：接收端收到推送帧后自动上报 `CmdDeliveryAck (0x0103)`，状态更新为已送达；
    * `MsgStatusRead (3)`：接收端激活窗口或进入会话后上报 `CmdReadReceipt (0x0401)`，状态更新为已读并记录已读游标。
  * **消息撤回**：支持发信人 2 分钟内双向撤回，撤回后原消息替换为“消息已撤回”。
  * **消息删除与清空**：支持用户删除指定消息或清空会话历史（严格校验会话成员权限）。
  * **引用与回复**：支持引用历史消息回复，UI 呈现原消息缩略预览。
* **FR-CHAT-03 分布式时序与弱网补偿**：
  * **分布式单调递增 SeqId**：每个单聊会话/群聊会话独立生成单调递增的序列号。优先由 Redis 7 执行原子 `INCR`，若 Redis 不可用则平滑退化至数据库高水位预热锁分配，绝无重复与跳跃倒退。
  * **增量拉取机制 (Sync)**：客户端断网重连后，携带本地最大 `last_seq_id` 向服务端发起增量同步请求（`CmdSyncReq 0x0300`），服务端返回区间差量数据，杜绝消息遗漏。
  * **并发安全发送**：网关连接实例封装 `SafeSend` 读写锁与原子状态，防止网络异常断连时触发并发向已关闭 Channel 写入导致崩溃。

### 3.4 群组服务 (`group`)
* **FR-GRP-01 群聊创建与解散**：支持自主建群与成员邀请；群主拥有解散群聊权限。
* **FR-GRP-02 角色与权限模型 (RBAC)**：
  * **群主 (Owner)**：管理群资料、委任/撤销管理员、解散群、移出成员、全员禁言、转让群主。
  * **管理员 (Admin)**：移出普通成员、单独禁言普通成员、修改群公告。
  * **普通成员 (Member)**：收发消息、退出群聊。
* **FR-GRP-03 动态群禁言体系**：
  * 支持全局全员禁言（仅群主/管理员可发言）。
  * 支持指定成员动态时长禁言（10分钟、1小时、1天等），到期自动解禁。
* **FR-GRP-04 群资产与资料**：群公告发布与历史公告查看、群成员名册检索。

### 3.5 实时音视频通话服务 (`webrtc`)
* **FR-RTC-01 1v1 音视频互通**：支持发起语音通话/视频通话，接收端震动与响铃提示弹窗。
* **FR-RTC-02 信令中继交互**：通过 WebSocket 传输 WebRTC 信令帧（`Offer`、`Answer`、`ICE Candidate`、`Hangup`、`Camera State` 等），仅在服务端内存中继路由，绝不落库。
* **FR-RTC-03 通话状态沉淀**：支持通话记录（主叫、被叫、通话类型、时长、挂断状态）历史记录存档与按用户隔离查询。

### 3.6 安全文件服务 (`file`)
* **FR-FILE-01 秒传机制**：客户端上传前计算文件 SHA-256 哈希值，服务端命中已存文件物理副本则复用存储，极速秒传。
* **FR-FILE-02 安全防盗链与临时签名**：
  * 文件上传成功后生成基于 HMAC-SHA256 的临时下载签名（`?sign=`），下载接口强校验签名时效性或合法 JWT Token。
  * 杜绝通过暴力遍历 `file_id` 下载全站未授权文件的安全漏洞。
* **FR-FILE-03 路径穿越防护**：对存储路径进行标准化解析与目录沙箱校验，严格禁止通过构造相对路径读取宿主机系统敏感文件。

### 3.7 AI 智能辅助与文本增强 (`ai`)
* **FR-AI-01 多模型上游适配**：内置 DeepSeek、OpenAI、Ollama 等主流大模型接口适配器。
* **FR-AI-02 会话智能摘要**：支持针对长文本会话历史提取核心议题、关键行动项与行动摘要。
* **FR-AI-03 智能回复与润色**：根据聊天上下文为用户一键生成快捷回复草稿。
* **FR-AI-04 密钥安全保护**：用户自备的 API Key 在服务端做持久化存储，前端读取时强制脱敏（如 `sk-******abcd`），保存配置时具备防误覆盖机制。

## 4. 三端客户端体验规范

### 4.1 Web 网页端
* **视觉标准**：基于现代 Tailwind CSS，采用 Telegram / Linear 风格的高质感深色/浅色主题、毛玻璃背景（Backdrop Blur）、平滑阴影与微动效。
* **交互体验**：全局快捷键（`Ctrl+K` 快速呼出全局搜索，`Enter` 发送消息，`Ctrl+Enter` 换行），无感 WebSocket 断线平滑重连。

### 4.2 Windows / macOS 桌面端 (Tauri v2 + Rust)
* **原生架构**：使用 Rust 作为 native host，无任何 Node.js/Chromium 臃肿运行环境。
* **系统集成**：
  * 支持最小化至系统托盘（Tray Icon），新消息闪烁提醒。
  * 窗口拖拽、文件拖拽入窗发送、快捷键响应。
  * 性能指标：空闲内存占用 ≤ 40MB，安装包体 ≤ 15MB。

### 4.3 Android 移动端 (Kotlin + Jetpack Compose)
* **纯原生架构**：采用 Google 官方推荐的声明式 UI 框架 Jetpack Compose，拒绝 WebView 壳应用。
* **移动端特性**：
  * 原生手势滑动、触控震动反馈（Haptic Feedback）。
  * 移动端前台服务（Foreground Service）配合保活策略，减少弱网断连。
  * 集成 Google WebRTC Native SDK 保证移动端音视频低延迟与硬件编解码支持。

## 5. 非功能性需求 (NFR)

* **NFR-01 吞吐量与时延**：
  * **单机模式**：SQLite WAL 支撑 ≥ 1,000 同时在线长连接；内网单聊消息端到端交付时延 P95 ≤ 50ms。
  * **集群模式**：Gateway + Logic + Kafka 分布式集群支持弹性水平扩容至 10,000+ 并发连接，消息推送峰值削平延迟 < 100ms。
* **NFR-02 部署与运维便捷性**：
  * 支持单个原生可执行文件分发（零中间件极简部署）。
  * 亦支持基于 Docker Compose 一键拉起微服务全家桶（Gateway、Logic、Transfer、Kafka KRaft、Etcd、Redis 7、MySQL 8、Prometheus）。
* **NFR-03 安全合规**：
  * 密码强制采用 `bcrypt` 强哈希存储。
  * 接口全面杜绝调试期越权后门，强制全链路验证 JWT。
  * 历史记录与消息操作强校验会话成员归属，阻断水平越权（IDOR）。
  * 静态资源与附件下载采用 HMAC-SHA256 签名鉴权防盗链，存储路径强制沙箱边界限制。
* **NFR-04 生产级可观测性**：
  * 各微服务节点统一集成 Prometheus 监控库，对外提供 `/metrics` HTTP 采集端点。
  * 实时上报连接指标、消息吞吐、投递回执统计与业务耗时分布。
