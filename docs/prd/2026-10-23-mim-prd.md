# Mim (M Instant Message) 企业级即时通讯平台 - 产品需求文档 (PRD)

---

## 1. 文档概述与项目背景

### 1.1 项目定位
本项目（**Mim**，即 **M Instant Message**）定位为**工业级、高可用、跨三端（Web、Windows、Android）的即时通讯微服务系统**。
项目旨在彻底摆脱常规开源或教学类 IM 项目的“玩具化”与“演示化”标签，站在大型企业级架构师与技术 Leader 的视角，设计并实现一套具备**金融级消息可靠性（At-Least-Once）、二进制高效通信、高并发削峰填谷、端到端隐私安全、全链路可观测性以及极致跨端性能**的现代化通信系统。

### 1.2 核心价值与简历杀手锏
1. **可靠性壁垒**：抛弃简陋的“WS 收到即转”模型，引入 **会话单调递增 SeqId + 读写扩散混合模型 + 客户端 ACK + 增量拉取（Sync）游标**，彻底解决弱网下的消息丢失、时序错乱与重复拉取。
2. **高效通信契约**：全系统采用 **Protobuf 二进制协议** 传输（体积削减 60%+，编解码性能提升 5-10 倍），搭配自研二进制帧头（魔数、版本、命令字、校验和）。
3. **三端极致原生体验**：
   * **Windows 桌面端**：**坚决杜绝 Electron**，采用 **Tauri v2 (Rust 核心)** 驱动，内存占用 < 40MB，安装包 < 15MB，冷启动毫秒级。
   * **Android 移动端**：采用 **Kotlin + Jetpack Compose 纯原生**，提供 120Hz 丝滑交互、后台保活、硬件级音视频编解码支持。
   * **Web 网页端**：基于 **Tailwind CSS + 现代化轻质感设计系统**（暗黑/浅色毛玻璃、流式交互、丰富微动效），彻底重构原版较为粗糙的默认样式。
4. **工业级可观测性与压测支撑**：集成 **OpenTelemetry + Jaeger 全链路分布式追踪**，附带 **10,000+ 高并发连接实测压测报告与性能分析**。

## 3. 功能需求详述 (FR)

### 3.1 认证与账号服务 (`mim-auth`)
* **FR-AUTH-01 注册与多模式登录**：支持账号密码登录、邮箱/手机验证码登录，支持 OAuth2 第三方快速认证（如 QQ 登录）。
* **FR-AUTH-02 双 Token 无感续期**：采用 `AccessToken (短效，2小时)` + `RefreshToken (长效，14天)` 机制，客户端请求拦截器自动无感续签。
* **FR-AUTH-03 多端登录与互踢策略**：
  * 支持规则：**同类型客户端互踢，不同类型客户端共存**（即允许 1 个 Web + 1 个 Windows 桌面 + 1 个 Android 手机同时在线）。
  * 状态同步：新端上线主动向旧端推送 `KICK_OUT` 下线通知。
* **FR-AUTH-04 账号安全与注销**：支持重置密码、设备管理列表查看与手动下线、账号软注销。

### 3.2 用户与关系链服务 (`mim-user`)
* **FR-USER-01 个人资料与头像裁剪**：用户基本信息（昵称、签名、性别、生日、城市），支持前端图片在线裁剪并生成缩略图。
* **FR-USER-02 隐私与防骚扰设置**：
  * 查找权限：允许通过账号/手机/昵称搜索，或完全关闭被搜索通道。
  * 加好友验证方式：允许任何人直接添加、需要验证消息、需要正确回答问题、拒绝任何人添加。
* **FR-USER-03 好友关系全流程流转**：
  * 发起好友申请 -> 填写验证信息/回答问题 -> 接收端实时红点通知与申请列表展示。
  * 状态机流转：`待审核(PENDING)`、`已同意(AGREED)`、`已拒绝(REJECTED)`、`已忽略(IGNORED)`。
* **FR-USER-04 好友管理**：修改好友备注名、特别关心/置顶、好友黑名单机制、双向/单向删除。
* **FR-USER-05 实时在线感知**：基于 Redis 状态机管理在线/离线/隐身状态，好友上线向互为好友且处于活跃会话的客户端广播上线事件。

### 3.3 实时即时通讯系统 (`mim-chat`)
* **FR-CHAT-01 消息类型全覆盖**：
  1. **纯文本与富文本**：支持 Markdown 片段、URL 自动识别与卡片化预览。
  2. **表情与表情包**：Unicode Emoji 表情面板、动态 GIF/Sticker 表情包发送。
  3. **图片消息**：支持点击大图预览、多图画廊轮播、拖拽上传、剪切板一键粘贴图片上传。
  4. **语音留言**：客户端录音时长波形展示、音频即时编码上传、按秒播放并支持倍速播放。
  5. **视频消息**：内嵌轻量级播放器、首帧封面自动提取、全屏播放。
  6. **文件消息**：根据后缀智能展示专业文件图标（PDF/Word/Excel/ZIP 等），展示文件大小与下载进度条。
* **FR-CHAT-02 消息高阶交互**：
  * **消息撤回**：支持 2 分钟内双向撤回，撤回后原消息替换为“xx 撤回了一条消息”，支持发信人点击“重新编辑”。
  * **引用与回复**：支持引用特定历史消息回复，UI 呈现原消息缩略预览，点击引用框自动高亮并平滑滚动到原消息位置。
  * **消息状态感知**：发送中（Loading）、已发送（服务端接收）、已送达（对端接收 ACK）、已读（对端已打开会话）。
* **FR-CHAT-03 消息时序与可靠性保证 (核心架构亮点)**：
  * **单调递增 SeqId**：每个单聊会话/群聊会话独立生成单调递增的序列号。
  * **增量拉取机制 (Sync)**：客户端断网重连后，携带本地最大 `last_seq_id` 向服务端发起增量拉取，服务端返回区间差量数据，杜绝丢消息。
  * **客户端 ACK 与去重**：客户端发送消息携带唯一 `client_msg_id`，服务端利用 Redis 幂等窗口去重，确保弱网重试不重复入库。

### 3.4 企业级群组服务 (`mim-group`)
* **FR-GRP-01 群聊创建与解散**：支持直接建群与联系人多选穿梭框建群；群主拥有唯一解散群聊权限。
* **FR-GRP-02 角色与权限模型 (RBAC)**：
  * **群主 (Owner)**：管理群资料、委任/撤销管理员、解散群、移出任意成员、全员禁言。
  * **管理员 (Admin)**：审批入群申请、移出普通成员、单独禁言普通成员、修改群公告。
  * **普通成员 (Member)**：收发消息、邀请好友（若群开启权限）、退出群聊。
* **FR-GRP-03 细粒度群禁言体系**：
  * 支持全局全员禁言（仅群主/管理员可发言）。
  * 支持指定成员动态时长禁言（10分钟、1小时、1天、自定义时间），到期自动解禁。
* **FR-GRP-04 群资产与资料**：群头像变更、群公告发布与历史公告查看、群文件列表沉淀与独立下载。

### 3.5 实时音视频通话服务 (`mim-webrtc`)
* **FR-RTC-01 1v1 音视频互通**：支持发起语音通话/视频通话，接收端震动与响铃提示弹窗。
* **FR-RTC-02 信令交互体系**：通过 WebSocket 实现 `Offer`、`Answer`、`ICE Candidate` 交换及通话挂断、拒绝、超时未接听信令流转。
* **FR-RTC-03 呼叫流转状态**：
  * `CALLING`（呼叫中） -> `RINGING`（振铃中） -> `CONNECTED`（通话建立） -> `ENDED`（正常挂断） / `REJECTED`（已拒绝） / `MISSED`（未接听）。
* **FR-RTC-04 通话体验**：Web/Windows 画中画（PIP）视图、本地摄像头翻转/静音/扬声器切换、通话计时沉淀至聊天记录。

### 3.6 安全文件服务 (`mim-file`)
* **FR-FILE-01 秒传机制**：客户端上传前计算文件 SHA-256 哈希值，服务端命中已存文件则直接返回 URL，零等待秒传。
* **FR-FILE-02 分块上传与断点续传**：大文件（> 10MB）切片上传，断网可续传，避免重复上传。
* **FR-FILE-03 安全访问与临时鉴权**：文件防盗链白名单机制、私有文件带时效性临时 Token 预览。

### 3.7 全局配置、审计与日志服务 (`mim-settings` & `mim-log`)
* **FR-SYS-01 动态配置热更**：系统级参数（单次上传上限、撤回时效、敏感词过滤列表）支持后台动态修改且无需重启服务。
* **FR-LOG-01 全链路操作与运行日志**：基于 Kafka 消息总线削峰，异步消费并记录系统操作行为（包含 TraceId、客户端真实 IP、IP 归属地、响应延迟）。
* **FR-LOG-02 日志审计后台**：支持针对 TraceId、用户 ID、服务模块、状态码的高效联合过滤与 JSON 格式化检索。

### 3.8 差异化创新功能 (Resume Highlights)
* **FR-INO-01 混合读写扩散模型**：单聊采用**写扩散**（各端拥有独立消息收件箱，查询极快）；大群聊（> 500人）自动平滑降级为**读扩散**（群成员共享群消息存储，仅维护已读游标），避免群消息扩散写导致存储雪崩。
* **FR-INO-02 端到端会话加密 (E2EE - 选配插件)**：基于 ECDH (Curve25519) 密钥协商 + AES-256-GCM 算法。私聊消息由发送端加密，服务端仅转发二进制密文（无明文、无私钥），只有对端可以解密。
* **FR-INO-03 AI 会话助手与群聊未读摘要**：针对群聊堆积的未读长消息，一键调用 LLM 接口输出 3 条结构化核心纪要，支持长文本一键翻译与多语言润色。

## 4. 三端客户端体验规范

### 4.1 Web 网页端
* **视觉标准**：基于现代 Tailwind CSS，采用 Telegram / Linear 风格的高质感深色/浅色主题、毛玻璃背景（Backdrop Blur）、平滑阴影与微动效。
* **交互体验**：全局快捷键（`Ctrl+K` 快速呼出全局搜索，`Enter` 发送消息，`Ctrl+Enter` 换行），无感 WebSocket 断线平滑重连。

### 4.2 Windows 桌面端 (Tauri v2 + Rust)
* **原生架构**：使用 Rust 作为 native host，无任何 Node.js/Chromium 臃肿进程。
* **系统集成**：
  * 支持最小化至 Windows 系统托盘（Tray Icon），新消息闪烁提醒。
  * 原生全局快捷键唤出（如 `Ctrl + Alt + W` 置顶窗口）。
  * 窗口拖拽、贴边吸附、原生文件拖拽入窗发送。
  * 性能红线：空闲内存占用 ≤ 40MB，安装包体 ≤ 15MB。

### 4.3 Android 移动端 (Kotlin + Jetpack Compose)
* **纯原生架构**：采用 Google 官方推荐的声明式 UI 框架 Jetpack Compose，拒绝 WebView 壳应用。
* **移动端特性**：
  * 原生手势滑动返回、下拉阻尼刷新。
  * 原生震动反馈（Haptic Feedback，如长按撤回、录音震动）。
  * 移动端前台服务（Foreground Service）配合保活策略，减少弱网断连。
  * 集成 Google WebRTC Native SDK 保证移动端音视频低耗电与硬件编解码。

## 5. 非功能性需求 (NFR)

* **NFR-01 吞吐量与时延**：单台 WebSocket 网关支持 ≥ 10,000 同时在线长连接；内网单聊消息端到端交付时延 ≤ 50ms。
* **NFR-02 高可用与容灾**：微服务无状态设计，通过 Etcd 动态服务注册与发现，单一业务节点故障由网关自动健康检查剔除。
* **NFR-03 安全合规**：密码采用 bcrypt 强哈希加盐存储；所有接口全面抵御 SQL 注入（GORM 参数化绑定）与 XSS 攻击；全链路启用 TLS/WSS 加密。
* **NFR-04 监控与可观测性**：各微服务埋点输出 Prometheus 性能指标（QPS、时延 P95/P99、连接数、Goroutine 数量），OpenTelemetry 跨服务透传 TraceID，Grafana 一键大盘呈现。
